# Cloudflare: як програма потрапить у мережу

Програма — статичні файли (`dist/`), які віддає Cloudflare Workers (static assets), так само як сайт way1ong.eu, ігри й Sky. Налаштування — `wrangler.jsonc` у корені. Адреса — `https://survival.way1ong.eu` (рішення Дмитра 27.11, погоджено з сесією сайту).

Стан на 27.11.2026: файли готові; воркера в Cloudflare ще немає.

## Одноразове підключення (робить Дмитро в панелі Cloudflare)

Кроки ті самі, що для Sky (`way1ong/way1ong-sky`, `docs/cloudflare.md`); панель з того часу могла трохи змінитись.

1. Спершу злити запит на злиття в `main`: Cloudflare збирає `main`, а в порожньому `main` збирати нічого.
2. Cloudflare → **Workers & Pages** → **Create application** → **GitHub** → репозиторій `way1ong/way1ong-survival`. Якщо репозиторію немає в переліку — дати застосунку Cloudflare у GitHub доступ до нього.
3. На екрані «Set up your application»:
   - **Project name:** `way1ong-survival` — так само, як `name` у `wrangler.jsonc` (інакше збірка падає). Панель підставляє назву репозиторію; вона збігається, але перевірити.
   - **Build command:** `npm run build`.
   - **Deploy command:** `npx wrangler deploy` (типове значення).
   - **Preview command:** не чіпати. Гілка — `main`, тека — корінь репозиторію.
4. **Deploy.** Якщо з'явиться «Request failed with status 500» — натиснути ще раз (з іграми 23.11 спрацювало з другого разу). Якщо збірка `main` впала без видимої причини — «Retry build» (так було із Sky 26.11).
5. Домен підключиться сам: у `wrangler.jsonc` записано `routes` з `survival.way1ong.eu`, а way1ong.eu уже в цьому акаунті Cloudflare. Перша викладка створить запис DNS і сертифікат.
6. Вкладка **Domains**: перемикачі **Production** (`….workers.dev`) і **Preview** лишити вимкненими — так записано й у `wrangler.jsonc`.

Після першої викладки сказати Claude: він запустить `npm run check:live` і звірить сторінку на справжній адресі зі збіркою.

## Що записано у `wrangler.jsonc` і чому

- `routes` з `"custom_domain": true` — адреса `survival.way1ong.eu`. Та сама адреса — у `src/config.ts`; тест `src/address.test.ts` стежить, щоб вони збігались.
- `"workers_dev": false` — без адреси `workers.dev`: у ній видно піддомен акаунта (як у сайту, ігор і Sky).
- `"preview_urls": false` — без відкритих адрес для гілок: Cloudflare пише їх у запити на злиття.
- `"previews": {}` — без цього блоку збірки гілок у Workers Builds падають (з'ясовано 23.11 на сайті).

Версію Node збірка бере з `.nvmrc` (та сама, що в Sky).

## Сторінки доходять без змін

На власному домені Cloudflare сам дописує до кожної сторінки скрипт свого Web Analytics — це проти правил «без стеження» й «без зовнішніх запитів». `public/_headers` додає до кожного файлу `Cache-Control: … no-transform`: тоді Cloudflare не має права змінювати наші файли дорогою. Тест `src/address.test.ts` стежить, щоб цей рядок не зник.

Перевірка на справжній адресі: `npm run build && npm run check:live` — запитує сторінку так, як браузер, і звіряє її байт у байт зі збіркою, а ще перевіряє, що маніфест, службовий скрипт і іконка на місці.

## Перевірити на телефоні після першої викладки

- Відкрити `survival.way1ong.eu`: розділи, меню, зміна мови.
- Android (Chrome, Samsung Internet): меню → «Встановити програму» → іконка з'явиться на екрані.
- iPhone: «Поділитися» → «На початковий екран».
- Вимкнути інтернет і відкрити програму з іконки — має відкритись.

## Перевірено тут (27.11.2026)

- `npx wrangler deploy --dry-run` читає 13 файлів із `dist/` (нічого не викладає).
- `npm run audit`: шість розмірів екрана, три мови, світла й темна тема, клавіатура, дуже великий текст, без інтернету — без зауважень.
- `npm run check:update`: відкрита програма каже про нову версію, «Оновити» перемикає на неї, хрестик відкладає.
- Не перевірено: встановлення на справжньому телефоні.
